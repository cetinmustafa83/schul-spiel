## 1. Vision, goals, non-goals

### 1.1 Vision
Pupils climb a 15-step prize ladder to **500,000 Taler** by answering multiple-choice questions, using jokers and nerve — while *unknowingly* repeating exactly the school material they have already been taught. The game is the hook; **repetition and mastery of the real German curriculum** is the purpose.

### 1.2 Goals
- G1. A polished, game-show-style experience (graphics, animation, sound, jokers) that children aged 10–14 actually want to replay.
- G2. Questions strictly matched to the player's **school type** and **grade**: easy basics first, climbing to the player's current grade level. **Never content from a higher grade** (hard invariant, see §6).
- G3. **Zero personal data beyond a pseudonymous player name, school type, grade and PIN.** No e-mail, no phone, no real-name requirement, no tracking, no third-party services.
- G4. Installable PWA (phone, tablet, desktop), offline-capable for training mode.
- G5. Learning value: explanation after each answer, personal "Wiederholungsstapel" (review deck) of missed questions, topic mastery overview.

### 1.3 Non-goals (v1)
- No real money, no prizes, no gambling mechanics, no in-app purchases, no ads, no loot boxes.
- No chat, no user-generated content visible to others, no friends list, no uploads.
- No teacher/class accounts (see roadmap v2 for anonymous class codes).
- No runtime AI/LLM calls (AI is used only offline for content generation; the running game contains no AI and sends no data to AI services).
- No religion/Ethik content in v1 (state-specific and sensitive). No Latin/French in v1.

## 2. Product principles & hard rules

These are non-negotiable and override convenience.

1. **No hardcoded values.** Game rules (ladder amounts, safe levels, tier weights, timers), school types, grades, subjects, topics, texts that may change, achievement definitions — all DB-driven or env-driven. Defaults ship as **seed migrations**, not as constants in code.
2. **No mock data.** Every screen reads real data from the API/DB. Seed data = real, reviewed content.
3. **SQLite** as the database (WAL mode). Self-hosted via **Dokploy + Traefik** on the DFM VPS (EU/Germany).
4. **Privacy by design & default** (Art. 25 DSGVO). Collect the minimum; delete automatically.
5. **Curriculum safety invariant:** no question may ever be shown to a player whose track/grade has not yet covered its topic.
6. **Child-first UX:** no dark patterns, no streak-guilt, no manipulative timers or notifications, no social pressure.
7. **Server-authoritative gameplay:** correct answers never leave the server in ranked mode.
8. **Everything original:** own name, mascot, visuals, music, sound (see §4).
9. **One design system**, consistent everywhere; touch-first, works on phone, tablet and desktop.
10. **No duplicate functionality** across screens (e.g., settings only in Settings, privacy info only in Datenschutz).

## 4. Brand, IP safety & naming

### 4.1 IP safety (important)
The TV format "Who Wants to Be a Millionaire?" / "Wer wird Millionär?" has protected **name, logo, music, studio look (blue stage, hexagonal answer plates, lighting) and mascot-free trade dress**. The *mechanics* (15 questions, 4 answers, safe levels, 50:50 / audience / phone jokers) are generic quiz mechanics and may be used.

**Therefore:**
- Do **not** use the names "Millionär", "Millionaire", "Wer wird…", the show's logo, fonts, music, sound effects, studio colours/hexagon plates, or the host.
- Prize unit is a virtual, clearly fictional currency (**Taler**), shown explicitly as "Spielgeld — keine echten Preise".
- Own visual identity (§11), own music/sfx (§12).

### 4.2 Working name
**Wissensgipfel** — "knowledge summit". The ladder is visualised as a **mountain climb** (15 stations to the summit at 500,000 Taler).
Alternatives (to check for trademark conflicts before launch ⚖️): *Gipfelstürmer*, *Quizgipfel*, *Lernleiter*.

### 4.3 Mascot
**Lumi**, a friendly owl (original character design; gender-neutral, neutral expressions: thinking, cheering, sympathetic, surprised). Lumi acts as host voice in text bubbles and as the "Freund" joker.

### 4.4 Tone of voice
German, informal **"du"**, short sentences, encouraging, never sarcastic. Wrong answer = "Knapp daneben! Lumi erklärt dir, warum." Never "Falsch!" in red-alarm style.

## 5. Game design

### 5.1 Core loop
1. Player logs in → Home → **"Spiel starten"**.
2. Game generates 15 questions (§6) → player climbs the ladder.
3. Each question: read → (optionally use a joker) → pick A/B/C/D → **"Final?" confirmation** (large "Ja, final!" / "Nochmal überlegen") → reveal with suspense → explanation card → next.
4. Game ends by: wrong answer (drop to last safe level), walk-away ("Aussteigen" — keep current winnings), or reaching 500,000.
5. Result screen: winnings, topic breakdown, missed questions auto-added to **Wiederholungsstapel**, XP/badges.

### 5.2 Prize ladder (default seed; stored in DB table `ladder_levels`)

| Level | Taler | Safe? | Tier |
|---:|---:|:---:|:---:|
| 1 | 50 | | A |
| 2 | 100 | | A |
| 3 | 200 | | A |
| 4 | 300 | | A |
| 5 | 500 | ✅ (Sicherheitsstufe 1) | A |
| 6 | 1,000 | | B |
| 7 | 2,000 | | B |
| 8 | 4,000 | | B |
| 9 | 8,000 | | B |
| 10 | 16,000 | ✅ (Sicherheitsstufe 2) | B |
| 11 | 32,000 | | C |
| 12 | 64,000 | | C |
| 13 | 125,000 | | C |
| 14 | 250,000 | | C |
| 15 | **500,000** | 🏔️ Gipfel | C |

- Wrong answer → fall back to the highest safe level reached (0 if none).
- "Aussteigen" available before locking in an answer from level 2 on.
- Ladder is data-driven: admins may change amounts/safe levels in the back-office without a deploy.

### 5.3 Jokers (each once per game; all configurable on/off in DB)

| Joker | Name (UI) | Behaviour |
|---|---|---|
| 50:50 | **50:50** | Server removes two wrong answers. Animated "poof" of the two plates. |
| Audience | **Klassen-Umfrage** | Shows animated bar chart. Percentages come from **real aggregated answer statistics** of that question when ≥ 30 answers exist, else from a difficulty-based model. Labelled "Umfrage unter Mitspielern" (never claims to be a real class). Can be wrong occasionally, as real polls are. |
| Phone | **Lumi fragen** (Freund) | Lumi gives an opinion with a confidence phrase ("Ich bin mir ziemlich sicher…", "Hmm, ich tippe auf…"). Correctness probability decreases with ladder level (configurable, e.g. 95 % → 60 %). Teaches critical thinking: Lumi can be wrong. Phrases from DB, varied. |
| Switch | **Frage tauschen** | Replaces the current question with a fresh one of the same level/tier (counts as used). |

Joker state is server-side; all joker results are generated server-side.

### 5.4 Timer (accessibility-aware)
Setting (per player, default **off**): `Aus` / `Entspannt 60 s` / `Challenge 30 s`. Timer never shown as a loud countdown; soft ring around the question card. Timeout = counts as "no answer" → treated as wrong (only if timer is enabled).

### 5.5 Modes

| Mode | Description | Ranked/Scored |
|---|---|---|
| **Gipfel-Spiel** | The 15-question ladder game | Yes (private stats) |
| **Training** | Pick 1–N subjects/topics, endless or 10-question rounds, no ladder, no jokers, immediate explanation, unlimited tries | No |
| **Wiederholungsstapel** | Spaced repetition over previously missed questions (Leitner boxes 1–4: 1 day / 3 days / 7 days / 21 days; intervals in DB) | No |
| **Tagesquiz** | 5 questions/day, same for all players of same school type + grade (deterministic seed by date+track+grade); small bonus XP; **no streak penalty** | Light |
| **Offline-Training** (v1.1) | Downloaded question pack (200 questions), unranked | No |

### 5.6 Progression (non-manipulative)
- **XP & level** ("Bergsteiger-Rang": Wanderer → Kletterer → Gipfelstürmer …), earned from correct answers and completed games. Rank names in DB.
- **Badges** ("Abzeichen"), DB-defined (e.g., "Erste 5.000 Taler", "Mathe-Profi: 50 richtige Mathe-Antworten", "Gipfel erreicht", "Fehler-Besieger: 20 Wiederholungsfragen gemeistert").
- **Topic mastery** per subject: simple bars based on rolling accuracy; shown privately in Profile.
- **Private percentile**: "Du bist besser als 70 % der Spieler:innen in Klasse 6 Gymnasium" (computed from anonymous aggregates; shown only if ≥ 50 players in cohort).
- **Public leaderboard: OFF by default** (privacy by default). Optional opt-in "Bestenliste" showing only the pseudonymous display name (without tag), highest ladder level this week; opt-in requires a parent-info confirmation screen. ⚖️

## 6. Curriculum & question-selection engine (core logic)

### 6.1 Concepts

- **School type (Schulform)** chosen at registration. NRW-oriented v1 list (DB table `school_types`):

| Code | Label | Content track |
|---|---|---|
| `HS` | Hauptschule | `basic` |
| `RS` | Realschule | `mid` |
| `SEK` | Sekundarschule | `mid` |
| `GE` | Gesamtschule | `mid` (optional "Erweiterungsniveau" toggle → `advanced` for selected subjects; v1.1) |
| `GY` | Gymnasium | `advanced` |

  *Open decision:* Förderschulen and other Länder-specific types (e.g., Mittelschule, Oberschule, Stadtteilschule) — extensible via DB; v1 targets **NRW**. A Bundesland field is **not** collected in v1 (data minimisation); content is NRW-aligned and flagged as such in the info page. ⚖️/📚

- **Grade (Klasse):** 5, 6, 7, 8 selectable. Content for **grade 4 (Grundschule basics)** exists in the bank as foundation material but is *not* selectable as a player grade. (Optional later: allow 9, 10.)

- **Question attributes relevant for selection:**
  - `intro_grade_hs`, `intro_grade_rs`, `intro_grade_gy` — **the grade in which that topic is first taught on that track** (nullable = not part of that track's curriculum, or not yet verified). SEK/GE use the `mid` column.
  - `difficulty` 1–5 (relative difficulty *within* its introduction grade).
  - `subject_id`, `topic_id` (links to curriculum map).
  - `status` must be `published`.

### 6.2 HARD INVARIANT (must be enforced in code AND tested)

> For player grade **N** and track **T**: a question is eligible **only if** `intro_grade_T IS NOT NULL AND intro_grade_T ≤ N`, `status = 'published'`, and its topic is flagged `active` for track T.

Example: Gymnasium, Klasse 6 → eligible: intro grade 4, 5, 6. **Never 7 or 8.** A question with `intro_grade_gy = NULL` is *never* shown to Gymnasium players.

Enforced at three layers:
1. SQL query filter (primary).
2. Post-filter assertion in the selection service (throws + logs if violated; the game falls back to a safe replacement).
3. CI property test: simulate ≥ 100,000 games across all (track, grade) combinations; assert zero violations (see §17).

### 6.3 Tier composition (difficulty ladder across grades)

Let `k = N − g` where `g` = effective intro grade of the question on the player's track (k = 0: current grade; k = 1: one grade below; k ≥ 2: two or more below, including grade-4 basics).

Default weights (stored in `selection_profiles` / `selection_weights`, editable in admin):

| Tier | Ladder levels | difficulty allowed | k=0 | k=1 | k≥2 |
|---|---|---|---:|---:|---:|
| **A — Warm-up** | 1–5 | 1–2 | 10 % | 30 % | 60 % |
| **B — Mixed** | 6–10 | 2–3 | 35 % | 40 % | 25 % |
| **C — Challenge** | 11–15 | 3–5 | 70 % | 25 % | 5 % |

Additional rules:
- **Level 15** is always `k = 0`, `difficulty = 5`, if available (fallback to difficulty 4, then k=0 any).
- **Levels 13–14**: ≥ 80 % `k = 0` combined.
- If a weight bucket is empty (e.g., N = 5 has no `k ≥ 2` except grade 4), **renormalise** weights across non-empty buckets. For N = 5, the pool is grade 4 + grade 5 only.
- Within a bucket, difficulty is sampled so that it **rises monotonically-ish** along the ladder (e.g., difficulty target = round(1 + 4·(level−1)/14) ± 1, clamped to allowed range).
- **Subject diversity:** at most 2 consecutive questions from the same subject; every game covers ≥ 6 subjects (when available); no subject > 4 questions (configurable).
- **Subject availability per grade/track:** a subject appears only if the topic map has active topics for that grade/track (e.g., Chemie not before its introduction grade).
- **Freshness:** exclude questions the player answered in the last *X* games (default last 10 games ≈ 150 questions, or last 60 days; whichever is larger-pool-safe). If the pool is exhausted, relax to "least recently seen". Seen-history is stored per player (pseudonymous), purged with the account.
- **Same-game uniqueness:** no duplicate question or near-duplicate (same `cluster_id`) in one game.
- **Switch joker:** replacement drawn with identical constraints for that level, excluding all questions already used in this game.
- **Pool-size guard:** if the eligible pool for any (track, grade, tier) is smaller than a configurable minimum (default 60), the admin dashboard flags a **content gap**; the game still works with relaxation rules but logs `pool_relaxed`.

### 6.4 Selection algorithm (reference pseudocode)

```text
function buildGame(player):
  N = player.grade; T = player.track
  profile = loadSelectionProfile(T)                // DB
  used = []; seenRecently = loadSeen(player)       // DB
  for level in 1..15:
     tier = tierOf(level)                           // DB ladder_levels.tier
     w = renormalise(profile.weights[tier], availableKBuckets(N,T))
     bucket = sampleBucket(w)                       // k=0 / k=1 / k>=2
     targetDiff = difficultyTarget(level, tier)
     q = pick(
        eligible(N,T)                               // HARD INVARIANT
        .where(k in bucket, difficulty in tierRange(tier))
        .excluding(used, seenRecently, sameCluster(used))
        .respecting(subjectDiversityRules(used))
        .weightedByCloseness(difficulty, targetDiff)
        .random(seeded))
     assert(q.introGrade(T) <= N)                   // layer 2
     used.push(q)
  persist game + ordered question ids (answers stay server-side)
```

### 6.6 "Cumulative review" principle
The game is built for **repetition**: lower-grade material is deliberately mixed in (the tier weights). A grade-8 player still meets grade-5 basics in warm-up levels. This is intended and explained on the Game Setup screen ("Dein Gipfel enthält Wiederholung + Klasse-8-Wissen").

## 7. Question bank

### 7.1 Question formats
- **v1:** text multiple-choice, 4 options, exactly 1 correct.
- **v1.1:** + image questions (geometry figures, maps, animals) with **required alt text**; + simple ordering questions (optional).
- Max lengths: question ≤ 180 chars (Deutsch text-based questions ≤ 320), answer option ≤ 50 chars, explanation ≤ 240 chars.
- Reading level matches the **intro grade** (short sentences, no jargon beyond the topic).

### 7.2 Question record (see schema §14.5)
Fields: `text`, `options[4]`, `correct_index`, `explanation`, `subject_id`, `topic_id`, `intro_grade_hs/rs/gy`, `difficulty`, `cluster_id`, `media_id?`, `source_note` (e.g., "NRW KLP Mathematik Sek I, Bereich Zahlen"), `status` (`draft` → `auto_checked` → `in_review` → `published` / `rejected` / `retired`), `created_by` (`glm`/`template`/`human`), `reviewed_by`, `reviewed_at`, `version`.

### 7.3 Content quality rules
- Exactly one unambiguously correct answer; distractors plausible but definitely wrong.
- No "alle genannten", "keine davon", no negations ("Welche ist NICHT…") in difficulty ≤ 2.
- No time-sensitive facts that go stale (current officeholders, records) — or flag with `expires_at`.
- No politics-of-the-day, no brands/advertising, no violence glorification, no stereotypes.
- Gender-fair, neutral names in examples (e.g., "Mia", "Can", "Jonas", "Aylin").
- Correct current German orthography (Duden); no regional-only terms unless taught.
- Option order randomised at serve time (store canonical order; shuffle per game, seeded; `correct_index` is mapped server-side).

### 7.4 Content pipeline (GLM-assisted, human-reviewed)

```text
[Topic seed list (from curriculum map)]
        │
        ▼
 1) GENERATE   — GLM with strict JSON schema (batch of 20 per topic/grade/difficulty)
        │       + deterministic TEMPLATE GENERATORS for Mathe (computed answers → guaranteed correct)
        ▼
 2) VALIDATE   — schema validation · length/format · profanity · duplicate/near-duplicate (normalised trigram)
        │
        ▼
 3) CROSS-CHECK — second, independent GLM pass: "solve it blind"; disagreement → quarantine
        │
        ▼
 4) READABILITY / POLICY check — reading level vs grade, forbidden-topic classifier
        │
        ▼
 5) HUMAN REVIEW — back-office queue (teacher/owner); approve / edit / reject; intro grade set per track
        │
        ▼
 6) PUBLISH → live; player "Frage melden" feedback loop → re-review; stats monitor (accuracy outliers flagged)
```

Rules:
- **No question is published without human approval** (at minimum, a 100 % review of grade-6+ Deutsch/Englisch/Geschichte/Erdkunde/Biologie; Math template output may be sample-reviewed at ≥ 10 %).
- Track-specific intro grades are **set by a human reviewer**, not by the model.
- Content volume target: **launch minimum** ≥ 25 published questions per (subject × grade × difficulty band [1–2 / 3 / 4–5]) for each subject active in that grade/track; overall **≥ 4,000** published at launch, **12,000+** within 6 months. A content-coverage report in admin shows gaps.
- Provenance recorded: generator, prompt version, model version.

**Generation prompt template (for GLM):**

```text
Du bist Fachlehrer:in für {fach} an einer {schulform} in Nordrhein-Westfalen.
Erstelle {n} Multiple-Choice-Fragen für Klasse {klasse}, Thema "{thema}", Schwierigkeit {difficulty}/5
(1 = sehr leicht für diese Klasse, 5 = sehr schwer für diese Klasse).
Regeln:
- Genau 4 Antwortoptionen, genau 1 richtige. Plausible, aber eindeutig falsche Distraktoren.
- Keine Verneinungsfragen bei Schwierigkeit <= 2. Kein "alle/keine der Antworten".
- Sprachniveau: Klasse {klasse}. Frage <= 180 Zeichen, Option <= 50 Zeichen.
- Erklärung (<= 240 Zeichen) in kindgerechtem Deutsch: warum ist die Antwort richtig?
- Nur Wissen, das laut Lehrplan bis einschließlich Klasse {klasse} behandelt wird. Nichts aus höheren Klassen.
- Keine tagesaktuellen Fakten, keine Marken, keine kontroversen politischen Themen.
Gib ausschließlich gültiges JSON zurück:
[{"text":"...","options":["...","...","...","..."],"correct_index":0,"explanation":"...","topic":"{thema}","difficulty":{difficulty},"suggested_intro_grade":{klasse},"curriculum_note":"..."}]
```

| **PIN** | 4 digits (child-friendly), see below |
| **Avatar** | Chosen from preset gallery (no uploads) — stored as `avatar_id` |

> *Interpretation of "isim":* The brief says "name". Recommended and implemented as a **pseudonymous Spielername**. If the owner insists on first names, allow it but keep the warning; the data model does not change. ⚖️

Nothing else. **No e-mail, no birth date, no address, no phone, no school name, no photo, no device identifiers.**

### 8.2 Login identity
- Because there is no e-mail, a login handle is **`Spielername#Tag`** where the **Tag** is a system-generated 4-digit number (e.g., `Mutiger Fuchs#4821`) shown prominently after registration ("Merke dir deinen Spielnamen + PIN!"). Login = Spielername + Tag + PIN.
- Registration ends with a **"Mein Zugang"** card (printable / screenshot-friendly): handle, reminder to remember the PIN, **Rettungscode**.

### 8.3 PIN security
- Stored with **argon2id** (per-account salt) — never reversible.
- Blocklist of trivial PINs (0000, 1234, 1111, 2580, birth-year-like patterns not detectable; only common list).
- Rate limiting: per handle (5 fails → 5 min lock, then exponential up to 1 h), per IP (in-memory counters only, never persisted), global throttling. Lock-out messages are friendly and non-revealing ("Das hat nicht geklappt. Versuch es später nochmal.").
- Constant-time responses; no account enumeration (same message for unknown handle and wrong PIN).
- Optional: PIN length 6 if the owner prefers stronger security (config `pin_length`).

### 8.4 Account recovery without e-mail
- **Rettungscode:** three random words from a kid-friendly German word list + 2 digits, e.g., `Mond-Tiger-Brot-47`; shown once at registration; stored hashed. Allows PIN reset. Parent info text recommends writing it down.
- No code, no recovery → "Neues Konto erstellen" (old data discarded). This is a conscious privacy trade-off, documented in Parent-Info.
- "Rettungscode neu erzeugen" in Settings (requires PIN).

### 8.5 Sessions
- Server-side session; **`HttpOnly`, `Secure`, `SameSite=Lax`** cookie, strictly necessary (no consent banner needed under TDDDG §25(2) — ⚖️ confirm). Sliding expiry 30 days; "Abmelden" button; "Auf diesem Gerät eingeloggt bleiben" toggle (default off on shared devices prompt).
- Shared-family-device friendly: quick **switch player** (re-enter PIN).

### 8.6 Account lifecycle & deletion
- **Self-service deletion** in Settings (requires PIN): immediate, hard delete of player + history.
- **Auto-delete:** accounts inactive **12 months** (config) are deleted; no warning possible (no contact data) — documented.
- **Data export** ("Meine Daten herunterladen", JSON) in Settings.
- Changing grade: **"Neue Klasse"** available (grade increments are common each school year); changing school type allowed; history is retained but selection uses the current grade.

### 8.7 Display-name uniqueness
Handle uniqueness is by (`display_name`, `tag`) — display names need not be unique.

## 9. DSGVO / privacy-by-design / child protection ⚖️

### 9.1 Data inventory

| Data | Purpose | Retention | Legal basis (to be confirmed ⚖️) |
|---|---|---|---|
| Spielername, tag, avatar | Identification in game | Until deletion / 12 months inactivity | Art. 6(1)(b)/(f) or consent — see 9.2 |
| Schulform, Klasse | Content selection | same | same |
| PIN hash, Rettungscode hash | Authentication | same | same |
| Game history (answers, scores, XP, badges, seen-question IDs, review deck) | Gameplay, learning features | same | same |
| Session token | Keep login | ≤ 30 days | TDDDG §25(2) strictly necessary |
| Server logs | Security/abuse | **7 days**, IP **truncated/anonymised** or not logged | Art. 6(1)(f) |
| Aggregated question stats | Quality + audience joker | Anonymous, indefinite | Not personal data (no player link, min. cohort sizes) |

**Not collected:** e-mail, IP in app DB, device fingerprint, analytics, advertising IDs, location, cookies other than the session cookie.

### 9.2 Legal-basis & parental-consent question (key open item ⚖️)
- Germany applies the **age of digital consent 16** (Art. 8 DSGVO) when consent is the legal basis; for a service offered directly to children below 16, consent requires parental authorisation.
- The product aims to process **only pseudonymous, minimal data necessary to provide the requested game** — arguably Art. 6(1)(b) (providing the service) / 6(1)(f). Without e-mail, **verifiable parental consent cannot be collected digitally**.
- **Recommended approach (to be validated by the DSB/lawyer):**
  1. Data minimisation as designed (pseudonym, no contact data).
  2. Child-friendly registration notice + clear **Parent-Info page** (reachable before registration) explaining the exact data, retention and rights.
  3. Mandatory tick: **"Meine Eltern wissen, dass ich hier spiele"** (informational, not a legal consent substitute) plus a **parent gate** (adult-level challenge, not child-guessable) in front of the Parent-Info and leaderboard opt-in.
  4. Optional opt-in features (leaderboard) are off by default.
  5. Documented **DSFA/DPIA** (children's data → recommended even if not strictly mandatory), **Verzeichnis von Verarbeitungstätigkeiten**, **TOMs** (Art. 32).
- Provide **two privacy notices**: *Kinder-Datenschutz* (reading level grade 5, short, icons) and *Eltern-/Vollversion* (formal Art. 13 DSGVO).
- Rights handling (access, erasure, rectification, portability): fulfilled via **self-service** (export, delete, edit). Because the operator cannot identify a person without account access, requests by e-mail to the operator are answered only with proof of control (login handle + PIN/Rettungscode) — documented in the notice (Art. 11 DSGVO).

### 9.3 Technical measures (privacy by design)
- Hosting: DFM VPS in Germany/EU; **no US cloud services, no CDNs, no external fonts/scripts/maps/analytics**, all assets self-hosted.
- HTTPS only (Traefik + Let's Encrypt), HSTS, strict **CSP** (`default-src 'self'`), `Referrer-Policy: no-referrer`, `Permissions-Policy` (no camera/mic/geo), `X-Content-Type-Options`, frame-ancestors none.
- No third-party SDKs. No service-worker analytics. No push notifications in v1.
- Logging without IP or with truncated IP + 7-day rotation; no request bodies logged; PINs never logged.
- DB at rest on encrypted volume; encrypted off-site backups (EU) with ≤ 30-day retention (backups contain deleted users for up to the retention window — document in notice).
- Admin accounts (adults) are separate from player accounts, with e-mail + strong password + TOTP; all admin actions in `audit_log`.
- Pen-test checklist & dependency scanning (npm audit, Dependabot-equivalent) in CI.

### 9.4 Child-protection / youth-media rules
- No ads, no external links in the game, no contact between users, no public free-text anywhere (display name is the only free text; filtered).
- No in-app purchases, no loot boxes, no randomised paid rewards (JMStV / USK-style principles).
- Age-appropriate content only (§7.3), question-reporting button visible at all times.
- **Imprint (Impressum, DDG §5)**, Datenschutz, Parent-Info reachable from every screen footer/Settings.
- Accessibility aligned with BFSG/WCAG 2.2 AA even though a free game may fall outside BFSG scope ⚖️.

### 9.5 Trademark/Copyright hygiene
See §4.1; all images, fonts (OFL), sounds (self-synthesised or CC0 with recorded licence), icons (own/ISC/MIT) tracked in `ASSET_LICENSES.md`.

## 13. Accessibility (WCAG 2.2 AA target)
- Full keyboard operation (A–D keys select, Enter confirms, J cycles jokers, Esc closes), visible focus.
- Screen-reader semantics: question as `role="group"` with `aria-labelledby`, answers as radio group, live region announces results ("Richtig! Erklärung: …"), ladder as a list with `aria-current`.
- Not colour-only (letters + shapes), contrast ≥ 4.5:1, text resizing to 200 % without loss.
- Dyslexia mode, adjustable text size, reduced motion, sound-off friendly (every sound has a visual equivalent).
- Optional **read-aloud** (v1.1) via the browser's built-in Web Speech API (on-device; no data leaves).
- Touch targets ≥ 48 px; no time pressure unless the player enables the timer; no flashing > 3 Hz.
- German plain-language option for instructions ("Leichte Sprache" for Help page, v1.1).

### 14.5 Database schema (SQLite; abridged DDL — full version in `docs/DATABASE.md` generated in Phase 1)

```sql
-- Reference data (all seeded by migrations, editable in admin)
CREATE TABLE school_types (code TEXT PRIMARY KEY, label TEXT NOT NULL, track TEXT NOT NULL CHECK(track IN ('basic','mid','advanced')), active INTEGER NOT NULL DEFAULT 1, sort INTEGER);
CREATE TABLE grades (grade INTEGER PRIMARY KEY, label TEXT NOT NULL, selectable INTEGER NOT NULL DEFAULT 1); -- 4 = basics, selectable=0
CREATE TABLE subjects (id INTEGER PRIMARY KEY, code TEXT UNIQUE, label TEXT NOT NULL, icon TEXT, color TEXT, active INTEGER DEFAULT 1);
CREATE TABLE topics (id INTEGER PRIMARY KEY, subject_id INTEGER REFERENCES subjects(id), code TEXT UNIQUE, label TEXT NOT NULL, curriculum_note TEXT);
CREATE TABLE topic_track_grade (topic_id INTEGER REFERENCES topics(id), track TEXT, intro_grade INTEGER NOT NULL, PRIMARY KEY(topic_id, track)); -- absence = not in curriculum

-- Game rules (data-driven)
CREATE TABLE ladder_levels (level INTEGER PRIMARY KEY, amount INTEGER NOT NULL, is_safe INTEGER NOT NULL DEFAULT 0, tier TEXT NOT NULL, label TEXT);
CREATE TABLE selection_weights (tier TEXT, k_bucket TEXT CHECK(k_bucket IN ('k0','k1','k2plus')), weight REAL NOT NULL, diff_min INTEGER, diff_max INTEGER, PRIMARY KEY(tier,k_bucket));
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, description TEXT);        -- timers, retention, joker probabilities, rate limits
CREATE TABLE jokers (code TEXT PRIMARY KEY, label TEXT, enabled INTEGER, config_json TEXT);
CREATE TABLE ranks (id INTEGER PRIMARY KEY, label TEXT, min_xp INTEGER);
CREATE TABLE badges (id INTEGER PRIMARY KEY, code TEXT UNIQUE, label TEXT, description TEXT, rule_json TEXT, icon TEXT);
CREATE TABLE phrases (id INTEGER PRIMARY KEY, kind TEXT, tone TEXT, text TEXT);             -- Lumi lines
CREATE TABLE content_pages (slug TEXT PRIMARY KEY, title TEXT, body_md TEXT, audience TEXT, updated_at TEXT); -- Datenschutz, Impressum, ...

-- Questions
CREATE TABLE questions (
  id INTEGER PRIMARY KEY, topic_id INTEGER NOT NULL REFERENCES topics(id), subject_id INTEGER NOT NULL REFERENCES subjects(id),
  text TEXT NOT NULL, opt_a TEXT NOT NULL, opt_b TEXT NOT NULL, opt_c TEXT NOT NULL, opt_d TEXT NOT NULL,
  correct_index INTEGER NOT NULL CHECK(correct_index BETWEEN 0 AND 3), explanation TEXT NOT NULL,
  difficulty INTEGER NOT NULL CHECK(difficulty BETWEEN 1 AND 5),
  intro_grade_hs INTEGER, intro_grade_rs INTEGER, intro_grade_gy INTEGER,   -- NULL = not in that track's curriculum
  cluster_id TEXT, media_id INTEGER, source_note TEXT, expires_at TEXT,
  status TEXT NOT NULL CHECK(status IN ('draft','auto_checked','in_review','published','rejected','retired')),
  created_by TEXT, prompt_version TEXT, model_version TEXT, reviewed_by INTEGER, reviewed_at TEXT, version INTEGER DEFAULT 1,
  created_at TEXT, updated_at TEXT
);
CREATE INDEX idx_q_select ON questions(status, subject_id, difficulty, intro_grade_gy, intro_grade_rs, intro_grade_hs);
CREATE TABLE question_stats (question_id INTEGER PRIMARY KEY, answered INTEGER, correct INTEGER, opt_counts_json TEXT); -- anonymous aggregates
CREATE TABLE question_reports (id INTEGER PRIMARY KEY, question_id INTEGER, reason TEXT, created_at TEXT, handled INTEGER DEFAULT 0); -- no player id stored
CREATE TABLE media (id INTEGER PRIMARY KEY, path TEXT, alt_text TEXT NOT NULL, license TEXT, source TEXT);

-- Players (pseudonymous)
CREATE TABLE players (
  id INTEGER PRIMARY KEY, display_name TEXT NOT NULL, tag TEXT NOT NULL, school_type TEXT NOT NULL REFERENCES school_types(code),
  grade INTEGER NOT NULL REFERENCES grades(grade), pin_hash TEXT NOT NULL, rescue_hash TEXT NOT NULL, avatar_id INTEGER,
  xp INTEGER DEFAULT 0, prefs_json TEXT, leaderboard_optin INTEGER DEFAULT 0,
  failed_logins INTEGER DEFAULT 0, locked_until TEXT, created_at TEXT, last_active_at TEXT,
  UNIQUE(display_name, tag)
);
CREATE TABLE sessions (token_hash TEXT PRIMARY KEY, player_id INTEGER REFERENCES players(id) ON DELETE CASCADE, expires_at TEXT);

-- Gameplay
CREATE TABLE games (id TEXT PRIMARY KEY, player_id INTEGER REFERENCES players(id) ON DELETE CASCADE, mode TEXT, grade_at_start INTEGER, track TEXT,
  current_level INTEGER, status TEXT, winnings INTEGER, jokers_json TEXT, started_at TEXT, ended_at TEXT);
CREATE TABLE game_questions (game_id TEXT REFERENCES games(id) ON DELETE CASCADE, level INTEGER, question_id INTEGER, option_order TEXT, answered_index INTEGER, correct INTEGER, answered_at TEXT, joker_used TEXT, PRIMARY KEY(game_id, level));
CREATE TABLE seen_questions (player_id INTEGER REFERENCES players(id) ON DELETE CASCADE, question_id INTEGER, last_seen_at TEXT, PRIMARY KEY(player_id, question_id));
CREATE TABLE review_deck (player_id INTEGER REFERENCES players(id) ON DELETE CASCADE, question_id INTEGER, box INTEGER, due_at TEXT, PRIMARY KEY(player_id, question_id));
CREATE TABLE player_badges (player_id INTEGER REFERENCES players(id) ON DELETE CASCADE, badge_id INTEGER, earned_at TEXT, PRIMARY KEY(player_id, badge_id));
CREATE TABLE topic_mastery (player_id INTEGER REFERENCES players(id) ON DELETE CASCADE, topic_id INTEGER, attempts INTEGER, correct INTEGER, PRIMARY KEY(player_id, topic_id));

-- Admin
CREATE TABLE admin_users (id INTEGER PRIMARY KEY, email TEXT UNIQUE, pw_hash TEXT, totp_secret_enc TEXT, role TEXT CHECK(role IN ('owner','editor','reviewer')), active INTEGER);
CREATE TABLE audit_log (id INTEGER PRIMARY KEY, admin_id INTEGER, action TEXT, entity TEXT, entity_id TEXT, meta_json TEXT, at TEXT);
```
Deleting a player cascades to all gameplay tables (privacy requirement). Aggregates (`question_stats`) never link back to a player.

### 14.6 Key services
- `SelectionService` (§6) · `GameService` (state machine: created → in_progress → finished/abandoned; idempotent answer handling; server timestamps) · `JokerService` · `ScoringService` (ladder/safe-level math from DB) · `AuthService` · `ReviewService` (Leitner) · `DailyService` (deterministic seed) · `RetentionJob` (nightly: delete inactive accounts, rotate logs, purge abandoned games) · `StatsJob` (percentiles with min-cohort rule).

### 14.7 Security checklist
argon2id params tuned (≥ 19 MiB, t=2); rate limits; CSRF protection (SameSite + custom header); strict input validation (Zod) on every route; output escaping (no `v-html` without sanitisation); CSP without `unsafe-inline` (nonce/hash for the critical inline snippet only); dependency pinning; secrets via env; admin 2FA; backup restore drill; anti-cheat (server-side answer check, per-question minimum-time sanity flag); no PII in logs; SQL via parameterised Drizzle queries only.

### 14.8 Deployment (Dokploy + Traefik)
Single container (`api` serving `/` static + `/api`), volume `/data` (SQLite + media), env vars: `NODE_ENV`, `DATABASE_PATH`, `SESSION_SECRET`, `ADMIN_BOOTSTRAP_*`, `LOG_RETENTION_DAYS`, etc. Healthcheck `/healthz`. Traefik: HTTPS redirect, HSTS, security-header middleware, compression. Nightly `sqlite3 .backup` → age-encrypted → EU object storage/VPS; restore documented.

## 16. Admin / content back-office (desktop-first)

- **Auth:** e-mail + password (argon2id) + TOTP; roles `owner` (everything), `editor` (questions), `reviewer` (approve/publish). Session timeout 30 min idle.
- **Dashboard:** content coverage heatmap (subject × grade × track × difficulty), pool-size alerts, report queue, accuracy outliers (questions < 15 % or > 98 % correct with ≥ 50 answers), active players (anonymous counts only).
- **Question manager:** list/filter/search, inline edit, side-by-side diff, bulk status change, set intro grades per track (with warning when a question is available to a grade below its topic's intro), duplicate finder, import/export (JSON/CSV), media library with required alt text.
- **Review queue:** shows machine cross-check result; approve / edit / reject with reason.
- **Reports:** reasons aggregated per question; one-click "retire" or "send to review".
- **Rules editors:** ladder, tier weights, jokers, timer defaults, retention, rate limits, Lumi phrases, badges, ranks, content pages (Datenschutz etc.) with versioning (`updated_at`, history).
- **Compliance panel:** retention job status, last backup, last restore test, DSFA/VVT links.
- **No player-identifying views:** admins cannot browse individual players' histories (only aggregates); support actions (e.g., delete player on proven request) by handle only, audited.
